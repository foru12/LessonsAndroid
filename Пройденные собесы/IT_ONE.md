# Вопросы

### 1. **String Pool**

String Pool – это специальная область памяти в Java, расположенная в куче (heap), которая используется для хранения строк. Основная идея String Pool заключается в оптимизации использования памяти и увеличении производительности при работе со строками.

**Как это работает?**
- Когда вы создаёте строку с использованием литерала (например, `String s = "Hello";`), JVM сначала проверяет, есть ли такая строка в String Pool.
- Если строка уже существует, JVM просто возвращает ссылку на неё, а не создаёт новый объект.
- Если строки в String Pool нет, JVM добавляет её туда и возвращает ссылку.

**Пример:**
```java
String s1 = "Hello";
String s2 = "Hello";

// s1 и s2 указывают на один и тот же объект в String Pool
System.out.println(s1 == s2); // true
```

**Зачем это нужно?**
- **Экономия памяти:** Одинаковые строки хранятся в единственном экземпляре, что уменьшает затраты на память.
- **Повышение производительности:** Повторное использование строк уменьшает затраты на создание новых объектов.

**Особенности:**
- Строки, созданные с использованием ключевого слова `new` (например, `String s = new String("Hello");`), не добавляются в String Pool автоматически. Они создаются как отдельные объекты в куче.
- Можно явно добавить строку в String Pool, вызвав метод `intern()`:
  ```java
  String s1 = new String("Hello");
  String s2 = s1.intern(); // s2 теперь ссылается на объект в String Pool
  ```

**На что обратить внимание?**
- String Pool оптимизирует только неизменяемые строки, поэтому он применим только к типу String.
- Это ключевая концепция для понимания работы с памятью и оптимизации в Java.

### 2. **StringBuilder**

`StringBuilder` — это класс в Java, который используется для работы с изменяемыми строками. В отличие от класса `String`, объекты `StringBuilder` можно изменять без создания новых объектов в памяти, что делает его более эффективным для операций со строками, таких как конкатенация, вставка, удаление и изменение символов.

**Основные особенности:**
1. **Изменяемость:**
   - Объекты `StringBuilder` изменяемы. Это значит, что методы изменяют сам объект, а не создают новый.
   ```java
   StringBuilder sb = new StringBuilder("Hello");
   sb.append(" World");
   System.out.println(sb); // Hello World
   ```

2. **Не потокобезопасный:**
   - `StringBuilder` не синхронизирован, поэтому не рекомендуется для использования в многопоточной среде. Если нужна потокобезопасность, используется `StringBuffer`.

3. **Высокая производительность:**
   - За счёт отсутствия синхронизации `StringBuilder` быстрее, чем `StringBuffer`.

### 3. **StringBuffer**

`StringBuffer` — это класс в Java, который, как и `StringBuilder`, используется для работы с изменяемыми строками. Основное отличие от `StringBuilder` заключается в том, что `StringBuffer` потокобезопасен, так как его методы синхронизированы.

**Основные особенности:**
1. **Изменяемость:**
   - Объекты `StringBuffer` можно изменять, а методы изменяют текущий объект вместо создания нового.
   ```java
   StringBuffer sb = new StringBuffer("Hello");
   sb.append(" World");
   System.out.println(sb); // Hello World
   ```

2. **Потокобезопасность:**
   - Методы `StringBuffer` синхронизированы, что делает его безопасным для многопоточной среды. Это также делает `StringBuffer` медленнее по сравнению с `StringBuilder` в однопоточных приложениях.

3. **Высокая производительность в многопоточной среде:**
   - Подходит для случаев, когда требуется работа со строками в приложениях с несколькими потоками.

### 4. **Garbage Collector**

`Garbage Collector (GC)` — это механизм в Java, который автоматически управляет памятью, удаляя объекты, которые больше не используются, чтобы освобождать память в куче для новых объектов. Он избавляет разработчиков от необходимости вручную освобождать память, как в некоторых других языках (например, C++).

**Основные концепции:**
- **Куча (Heap):**
  GC работает в области памяти, называемой кучей. Куча делится на:
  - **Young Generation (Молодое поколение):** Новые объекты создаются здесь. Если объект переживает несколько сборок мусора, он перемещается в Old Generation.
  - **Old Generation (Старшее поколение):** Сюда попадают долгоживущие объекты.
  - **Metaspace (с Java 8):** Хранит метаинформацию о классах.

- **Достижимость объекта:** Объект считается недостижимым, если нет ссылок, ведущих к нему из активных объектов программы.

- **Корень достижимости (GC Root):** Начальная точка для поиска достижимых объектов. К GC Root относятся:
  - Локальные переменные в стеке.
  - Статические поля классов.
  - Активные потоки.

**Алгоритмы сборки мусора:**
1. **Mark-and-Sweep:** GC проходит от GC Root, отмечает все достижимые объекты, а затем удаляет недостижимые.
2. **Copying:** Используется для Young Generation. Объекты копируются из одной области в другую.
3. **Generational GC:** Делит кучу на поколения (Young, Old).
4. **Compact:** Устраняет фрагментацию памяти.

## 5. **Стек**
В стеке хранятся данные, которые связаны с выполнением методов:
- Локальные переменные.
- Аргументы методов.
- Адрес возврата.

**Пример:**
```java
void example() {
    int x = 10; // x хранится в стеке
}
```

---

## 6. **Куча**
Куча используется для хранения объектов, которые имеют длительный срок жизни. Объекты создаются с помощью оператора `new`.

**Пример:**
```java
String str = new String("Hello"); // Хранится в куче
```

---

## 7. **Виды ссылок**
1. **Сильные ссылки:** Объект не удаляется GC.
2. **Слабые ссылки:** Удаляются, если на объект нет сильных ссылок.
3. **Мягкие ссылки:** Удаляются только при нехватке памяти.
4. **Фантомные ссылки:** Для мониторинга удаления объекта.

## 8. **Дата классы в Kotlin**
Дата классы предназначены для хранения данных. Они автоматически генерируют полезные методы, такие как `toString()`, `equals()`, `hashCode()`.

**Пример:**
```kotlin
data class User(val name: String, val age: Int)
```

## 10. **Потоки Java**
Потоки используются для выполнения нескольких задач одновременно.

**Основные проблемы многопоточности:**
1. **Гонки данных:** Несколько потоков изменяют одни и те же данные.
2. **Deadlock:** Потоки блокируют друг друга.

**Решения:**
- Использование `synchronized`.
- Применение `ReentrantLock`.
- Работа с `volatile`.
