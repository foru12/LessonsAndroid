1. Чем отличаются val и var в Kotlin, и зачем тогда нужен const?
Ответ:

var – это изменяемая переменная (mutable variable), значение которой можно менять после инициализации.
val – это неизменяемая переменная (read-only), её значение нельзя изменить после инициализации, но при этом объект, на который она ссылается, может быть изменяемым.
const val – это compile-time константа. Она должна объявляться на уровне top-level или в объекте-компаньоне, быть примитивного типа или типа String. Значение const val известно на этапе компиляции и не может изменяться впоследствии. Такие переменные часто используются в качестве ключей или других неизменных значений, доступных на этапе компиляции.
2. Что такое data-классы и для чего они нужны?
Ответ:
Data-классы в Kotlin – это классы, предназначенные для хранения данных. При объявлении data class компилятор автоматически генерирует для него следующие методы на основе свойств первичного конструктора:

equals() и hashCode() – для корректного структурного сравнения объектов,
toString() – для удобного текстового представления объекта,
copy() – для создания копии объекта с возможностью изменения отдельных свойств,
componentN() функции – для деструктурирующего присваивания.
Data-классы помогают сократить шаблонный код (boilerplate) и делают код более читаемым и поддерживаемым, особенно когда класс используется для представления простых структур данных или DTO.

3. Какие требования к корректной реализации equals() и hashCode()?
Ответ:
К корректному переопределению equals() предъявляются следующие требования:

Рефлексивность: a.equals(a) должно быть true.
Симметричность: a.equals(b) должно давать тот же результат, что и b.equals(a).
Транзитивность: если a.equals(b) и b.equals(c), то a.equals(c).
Согласованность: повторные вызовы equals() на одних и тех же объектах без изменения их состояния должны возвращать один и тот же результат.
Сравнение с null: a.equals(null) должно возвращать false.
hashCode() должен быть согласован с equals(). Это означает, что если a.equals(b) == true, то a.hashCode() должен быть равен b.hashCode().

4. Как ведёт себя equals() и hashCode() у data-классов? Что, если свойство объявлено вне первичного конструктора?
Ответ:
У data-классов equals() и hashCode() генерируются компилятором и учитывают только свойства, объявленные в первичном конструкторе data-класса. Свойства, добавленные вне первичного конструктора или во вторичных конструкторах, не учитываются при сравнении на равенство и при вычислении хэш-кода.

Если вам нужно, чтобы дополнительные поля учитывались, придется вручную переопределять equals() и hashCode().

5. Можно ли переопределить методы componentN() не у data-классов?
Ответ:
Да, это возможно. componentN() – это обычные функции, которые могут быть определены в любом классе. Data-классы их генерируют автоматически, но при желании можно вручную определить component1(), component2() и т.д. в обычных классах, чтобы получить поддержку деструктурирующего присваивания.

6. Для чего нужен hashCode()?
Ответ:
hashCode() используется при работе с хэш-структурами данных (например, HashMap, HashSet). Он возвращает целочисленное значение (хэш-код) объекта, по которому объект будет помещен в "корзину" (bucket). При поиске элемента по ключу сначала определяется нужная корзина по hashCode(), а затем сравниваются объекты внутри этой корзины по equals().

Если hashCode() определен корректно и последовательно с equals(), то хэш-коллекции работают эффективно (приблизительно за O(1) по времени).

7. Что произойдет, если у всех объектов в HashMap будет одинаковый hashCode()?
Ответ:
Если все объекты дают одинаковый hashCode(), они попадут в одну и ту же корзину. Тогда при поиске конкретного ключа в этой корзине будет происходить линейный перебор всех объектов (сравнение по equals()), что приводит к деградации производительности с O(1) до O(n). Поэтому важно обеспечивать распределение хэш-кодов таким образом, чтобы коллизии были редкими.

8. Как реализовать конкатенацию строк в Kotlin?
Ответ:
В Kotlin можно конкатенировать строки несколькими способами:

Используя оператор +:
kotlin
Копировать код
val result = str1 + str2
С помощью интерполяции строк (String Template):
kotlin
Копировать код
val result = "$str1 $str2"
Через StringBuilder (неявно StringBuilder может использоваться под капотом при интерполяции в циклах):
kotlin
Копировать код
val builder = StringBuilder()
builder.append(str1).append(str2)
val result = builder.toString()
Наиболее идиоматичный способ – использовать интерполяцию строк, т.к. это проще и читабельнее.

9. Какие уровни видимости (модификаторы доступа) есть в Kotlin?
Ответ: Kotlin предлагает следующие модификаторы видимости:

public (по умолчанию) – доступен везде.
private – доступен только внутри того же класса или файла (если это top-level функция или свойство).
protected – доступен внутри класса и его подклассов.
internal – доступен внутри одного модуля (модуль – это, например, один Gradle-модуль).
10. Что такое inner class в Kotlin?
Ответ:
По умолчанию вложенные классы в Kotlin являются статическими, то есть не имеют ссылки на экземпляр внешнего класса. Если нужно, чтобы вложенный класс имел доступ к экземпляру внешнего класса, его объявляют как inner class. Внутри inner class можно обращаться к членам внешнего класса, используя this@OuterClass.

11. Зачем нужно ключевое слово inline?
Ответ:
Ключевое слово inline в Kotlin используется для функций высшего порядка, чтобы избежать накладных расходов на создание лямбд-объектов при каждом вызове и вызова функции через указатель. При inline компилятор встраивает тело функции прямо в место вызова, что может улучшить производительность. Это особенно полезно, когда вы часто передаете лямбда-функции в качестве аргументов.

12. Что такое sealed class и sealed interface и для чего они нужны?
Ответ:
sealed классы и интерфейсы ограничивают иерархию наследования. Это значит, что все возможные наследники должны быть объявлены в том же модуле и файле, что и сам sealed класс или интерфейс. Такой подход позволяет компилятору знать исчерпывающий набор вариантов, что упрощает проверки при использовании when-выражений: компилятор может подсказать, если вы не учли какой-то вариант. Это упрощает написание безопасного кода с полным покрытием вариантов.

13. Что такое assert в Kotlin?
Ответ:
assert – это механизм проверки условий, который выбрасывает AssertionError, если условие не выполняется. Используется для внутреннего тестирования и отладки, а не в продакшен-коде. В зависимости от настроек (например, флагов JVM) assert может быть отключён в релизной сборке, чтобы не влиять на производительность.

14. Каким оператором сравниваются ссылки на объекты?
Ответ:
Ссылочное сравнение в Kotlin производится оператором ===. Он возвращает true, если две переменные указывают на один и тот же объект в памяти. Для структурного сравнения используется ==, которое под капотом вызывает equals().

15. Что такое lateinit и lazy? В чём разница?
Ответ:

lateinit var – это отложенная инициализация изменяемой переменной (var), которая не может быть примитивного типа. Если обратиться к такой переменной до инициализации, будет выброшено UninitializedPropertyAccessException. Применяется, когда нельзя сразу инициализировать переменную, например в onCreate() Activity.

lazy – это делегат, который позволяет лениво инициализировать свойство. Значение вычисляется при первом обращении и кэшируется для последующих вызовов. Обычно lazy используется с неизменяемым свойством (val), инициализация происходит один раз и потом возвращается одно и то же значение.

Таким образом, lateinit – для отложенной инициализации без ленивости (инициализация произойдет где-то вручную), а lazy – для ленивой инициализации при первом обращении.

1. Что такое object в Kotlin и когда стоит его использовать?
Ответ:
object – это специальный вид объявления в Kotlin, который создает синглтон-объект. Он не требует явного создания экземпляра и существует в единственном экземпляре в рамках одного процесса. Использовать object можно для:

Object declaration: объявление единственного объекта прямо в коде (например, для хранения констант, вспомогательных методов или настроек).
Companion object: статический контекст внутри класса, который может содержать фабричные методы, константы, статические поля.
Object expression: анонимные объекты, похожие на анонимные классы в Java, для быстрого создания единичных экземпляров каких-либо реализаций интерфейсов или наследников.
Таким образом, object упрощает создание синглтонов и вспомогательных объектов без дополнительного шаблонного кода.

2. Что такое расширения (extension functions/properties) в Kotlin и когда они применяются?
Ответ:
Расширения – это возможность добавить новые методы или свойства к уже существующим классам без наследования или модификации их исходного кода. Объявляются они с помощью синтаксиса fun <ClassName>.newFunction() { ... }. Применяются для повышения удобочитаемости, переиспользования кода и инкапсуляции логики, когда нельзя или неудобно изменить исходный класс (например, если это библиотека или закрытый код).

3. Что такое inline-классы (value classes) в Kotlin?
Ответ:
Inline-классы (в более поздних версиях Kotlin – value classes) позволяют создавать обёртки над примитивными типами или другими объектами без накладных расходов на дополнительный объект в рантайме. Они помогают повысить безопасность типов (например, вместо String для id использовать UserId) и при этом не ухудшают производительность. При компиляции такие классы могут подставляться вместо реальных объектов, избегая лишних аллокаций.

4. Что такое tail recursion и как она поддерживается в Kotlin?
Ответ:
Tail recursion (хвостовая рекурсия) – это оптимизация, при которой рекурсивный вызов в конце функции может быть заменён компилятором на цикл, чтобы избежать переполнения стека. В Kotlin можно пометить функцию модификатором tailrec, если последний вызов функции – это рекурсивный вызов самой себя. Если все условия соблюдены, компилятор выполнит оптимизацию, и рекурсия будет работать без риска StackOverflowError на больших входных данных.

5. Что такое by-клаузи в Kotlin (делегирование свойств и классов)?
Ответ:

Делегирование свойств (by) позволяет передать логику получения и хранения значения свойства другому объекту (делегату). Например, val name by lazy { ... } откладывает инициализацию свойства до первого доступа.
Делегирование классов (class MyClass by SomeOtherClass()) позволяет реализовать паттерн "Декоратор", при котором класс перенаправляет все публичные вызовы к объекту-делегату, не переписывая методы вручную.
Делегирование упрощает код, уменьшает дублирование и повышает гибкость архитектуры.

6. Что такое operator-функции, как они определяются и зачем нужны?
Ответ:
operator-функции – это функции, помеченные ключевым словом operator, которые позволяют перегружать операторы в Kotlin. Например, можно определить operator fun plus(other: Something), чтобы использовать оператор + для пользовательского класса. Это улучшает читаемость кода, позволяет применять математические или логические операции к собственным типам более естественным образом.

Пример:

kotlin
Копировать код
data class Vector(val x: Int, val y: Int) {
    operator fun plus(other: Vector) = Vector(x + other.x, y + other.y)
}

// Использование:
val v1 = Vector(1,2)
val v2 = Vector(3,4)
val v3 = v1 + v2 // Vector(4,6)
7. Что такое инвариантность, ковариантность и контравариантность в контексте дженериков Kotlin?
Ответ:

Инвариантность: Тип-параметр не может быть заменён ни на более общий, ни на более специфичный тип. Например, MutableList<String> не является ни MutableList<Any> ни MutableList<CharSequence>.

Ковариантность (out): Позволяет использовать более общий тип вместо более конкретного. Например, List<out String> может рассматриваться как List<CharSequence>. Это безопасно, когда из контейнера только читают.

Контравариантность (in): Позволяет использовать более конкретный тип вместо более общего. Например, Comparable<in Number> может рассматриваться как Comparable<Int>. Это применимо, когда в контейнер только пишут (передают значения).

Таким образом, ковариантность/контравариантность позволяют более гибко использовать обобщённые типы, не теряя при этом безопасности типов.

8. Что такое reified-параметры в inline-функциях?
Ответ:
В обычных дженериках типовая информация стирается на этапе компиляции (type erasure). Однако в inline функциях с модификатором reified для параметра типа компилятор сохраняет эту информацию, что позволяет обращаться к типу во время выполнения. Это открывает возможности, недоступные при обычных дженериках, например:

kotlin
Копировать код
inline fun <reified T> isInstance(value: Any): Boolean {
    return value is T
}

val result = isInstance<String>("Hello") // true
Без reified вам бы пришлось передавать Class<T> как параметр.

9. Когда стоит использовать !! (double bang) оператор?
Ответ:
Оператор !! преобразует nullable-тип в non-null тип, выбрасывая NullPointerException при попытке использовать null значением. Применять его следует очень осторожно и лишь в тех случаях, когда вы на 100% уверены, что значение не будет null. Чаще рекомендуется использовать безопасные вызовы (?.), оператор ?:, или явные проверки на null, чтобы избежать NPE.

10. Объясните разницу между fold, reduce, map и flatMap в Kotlin-коллекциях.
Ответ:

map: Применяет функцию к каждому элементу коллекции и возвращает новую коллекцию из преобразованных элементов. Например, [1,2,3].map { it * 2 } -> [2,4,6].

flatMap: Применяет функцию, которая возвращает коллекцию для каждого элемента, и затем "выпрямляет" все результаты в одну коллекцию. Например, listOf("ab","cd").flatMap { it.toList() } -> ['a','b','c','d'].

reduce: Применяет аккумуляторную операцию к элементам коллекции, сводя коллекцию к одному значению, начиная со первого элемента. Например, [1,2,3].reduce { acc, i -> acc + i } -> 6.

fold: Аналогичен reduce, но позволяет задать начальное значение аккумулятора. Например, [1,2,3].fold(10) { acc, i -> acc + i } -> 16 (т.к. стартовое значение 10).

1. Чем object отличается от companion object?
Ответ:

object – это объявление синглтона, создающее единичный экземпляр класса или анонимного объекта. Он существует сам по себе.
companion object – это специальный блок внутри класса, по функционалу напоминающий статический контекст (как static в Java). Он предоставляет фабричные методы и константы класса. При этом фактически это объект, ассоциированный с классом, доступ к которому можно получить через MyClass.Companion или просто MyClass (при наличии определённых аннотаций или расширений).
Таким образом, companion object – «спутниковый» объект конкретного класса, а обычный object – автономная единица.
2. В чём разница между apply, with, run, let и also?
Ответ:
Эти функции-расширения (scope functions) помогают упростить код, выполняя действия над объектами или конфигурируя их. Основные различия:

let:

Вызывается на конкретном объекте: obj.let { ... }.
В лямбде объект доступен как it.
Возвращает результат лямбды.
Используется, когда нужно безопасно работать с nullable-значением или преобразовать объект.
run:

Вызывается на объекте: obj.run { ... }.
В лямбде объект доступен как this.
Возвращает результат лямбды.
Хорошо подходит для выполнения цепочки операций и возвращения результата вычисления.
with:

Принимает объект как аргумент: with(obj) { ... }.
В лямбде объект доступен как this.
Возвращает результат лямбды.
Позволяет обращаться к членам объекта без повторения имени переменной.
apply:

Вызывается на объекте: obj.apply { ... }.
В лямбде объект доступен как this.
Возвращает сам объект.
Часто используется для настройки (конфигурирования) объекта.
also:

Вызывается на объекте: obj.also { ... }.
В лямбде объект доступен как it.
Возвращает сам объект.
Используется, когда нужно выполнить побочные действия (логирование, валидацию) без изменения результата цепочки.
Итого:

let и run возвращают результат лямбды,
apply и also возвращают исходный объект,
with похож на run, но вызывается не как метод объекта, а с ним в качестве аргумента.
3. Как работать с рефлексией в Kotlin и чем KClass отличается от Class<*>?
Ответ:
Рефлексия в Kotlin позволяет анализировать классы, функции, свойства во время выполнения. Ключевые классы и интерфейсы находятся в пакете kotlin.reflect.

KClass – это класс из мира Kotlin-рефлексии, предоставляющий информацию о структуре Kotlin-класса (метаданные о функциях, свойствах, конструкторах и т.п.).
Class<*> – это класс из Java-рефлексии (java.lang.Class), предоставляющий низкоуровневую информацию о типах на уровне JVM.
При работе с KClass можно получить доступ к более «Kotlin-специфичной» метаинформации (например, к свойствам как к KProperty), тогда как Class<*> – чисто JVM-представление. Конвертировать KClass в Class<*> можно вызовом myKClass.java.
4. Что такое when выражение, чем оно отличается от switch в Java и что такое смарт-касты?
Ответ:

when в Kotlin – это более гибкий аналог switch из Java. Оно может проверять не только равенство значений, но и применять условия (например, проверки типа, диапазонов, предикаты). when может использоваться как выражение (возвращать значение) и как оператор.
В отличие от switch, when не требует обязательных break, и поддерживает исчерпывающие проверки, особенно в сочетании с sealed классами.
Смарт-касты – это автоматические преобразования типа переменной, когда компилятор уверен, что переменная определённого типа. Например, после проверки if (obj is String), внутри этого блока obj будет рассматриваться как String без явного приведения.
5. Что такое Sequence и чем оно отличается от Iterable?
Ответ:

Iterable при использовании операций высшего порядка (map, filter) производит операции неточно (eager) – сразу создаются промежуточные коллекции.
Sequence же выполняет операции лениво (lazy). При последовательных вызовах map, filter и т.д. данные обрабатываются по цепочке элементов без создания промежуточных коллекций. Результат получается при обходе последовательности. Это может повысить производительность при работе с большими наборами данных или при цепочках преобразований.
Пример:
listOf(1,2,3).map { ... }.filter { ... } – создаёт промежуточные коллекции,
listOf(1,2,3).asSequence().map { ... }.filter { ... } – превращает список в последовательность и операции применяются лениво.

6. Для чего нужен vararg параметр в функциях?
Ответ:
vararg позволяет определить параметр функции, принимающий переменное количество аргументов одного типа. Внутри функции этот параметр будет доступен как массив. Это упрощает вызовы функций, где количество аргументов заранее неизвестно.

Пример:

kotlin
Копировать код
fun printAll(vararg strings: String) {
    for (s in strings) {
        println(s)
    }
}

printAll("one", "two", "three")
7. Можно ли использовать именованные и опциональные параметры в Kotlin-функциях? Зачем это нужно?
Ответ:
Да, Kotlin поддерживает именованные и опциональные параметры:

Именованные параметры позволяют упростить чтение кода, особенно если у функции много параметров одного типа. Можно явно указывать имя параметра при вызове:

kotlin
Копировать код
fun createUser(name: String, age: Int = 18, isActive: Boolean = true) { ... }

createUser(name = "John", isActive = false)
Это улучшает читаемость и делает код менее подверженным ошибкам.

Опциональные параметры (параметры со значениями по умолчанию) позволяют не передавать значение для параметра, если есть дефолт. Это снижает количество перегрузок методов и делает код компактнее.

8. Что такое @JvmStatic, @JvmOverloads, @JvmField и зачем они нужны?
Ответ:

@JvmStatic: аннотация, используемая в companion object или object для генерирования статического метода в Java-байткоде. Это упрощает вызов Kotlin-кода из Java, делая его похожим на вызов статических методов.

@JvmOverloads: генерирует перегрузки функций для Java при наличии параметров по умолчанию. Если у Kotlin-функции есть параметры с дефолтными значениями, эта аннотация создаст несколько перегруженных методов без этих параметров для удобства вызова из Java.

@JvmField: делает свойство из object или companion object полем без геттеров/сеттеров, доступным как статическое поле в Java. Упрощает доступ к константам и объектам из Java-кода.

9. Что такое inline-классы (value classes) и какие ограничения у них есть?
Ответ:
Inline-классы (value classes) позволяют создавать типы-обёртки вокруг одного значения без накладных расходов на дополнительный объект. Они улучшают безопасность типов (например, различать UserId и ProductId, которые, по сути, могут быть строками). При компиляции inline-класс может быть “распакован” до примитива или другого класса, избегая аллокаций.

Ограничения:

Inline-класс может содержать только одно свойство в первичном конструкторе.
Нельзя иметь init блок или дополнительные свойства состояния.
Поскольку это, по сути, wrapper over a single value, наследование от других классов не поддерживается.
