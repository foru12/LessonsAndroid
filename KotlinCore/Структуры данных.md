# Структуры данных

**Структура данных** — это программная единица, позволяющая хранить и обрабатывать множество однотипных и/или логически связанных данных в вычислительной технике. Она используется для добавления, поиска, изменения и удаления данных. Структура предоставляет некоторый набор функций, составляющих её интерфейс.

## Структуры данных, не привязанные к языку:
- Массивы
- Стеки
- Очереди
- Связанные списки
- Деревья
- Хэш таблицы

# ArrayList

```kotlin
// Создание ArrayList из чисел с плавающей точкой
val prices: ArrayList<Double> = arrayListOf(10.5, 20.3, 15.8)
```

```java
// Создание ArrayList из целых чисел

```

## Ошибка при удалении элементов в for-each цикле

При использовании for-each цикла в `ArrayList` удаление элементов вызывает ошибку, потому что for-each цикл работает через итератор, а модификация списка (удаление элемента) нарушает состояние этого итератора.

### Причина ошибки

#### Модификация во время итерации:
- for-each цикл использует скрытый итератор (`Iterator`) для перебора элементов коллекции.
- Когда `Iterator` создаётся, он отслеживает состояние коллекции. Если коллекция модифицируется (например, элемент удаляется) вне самого итератора (например, через метод `remove()` `ArrayList`), это вызывает `ConcurrentModificationException`.

#### Fail-Fast поведение:
- Итераторы в `ArrayList` и других коллекциях Java имеют механизм fail-fast, который обнаруживает изменения коллекции после создания итератора.
- Если коллекция модифицируется после создания итератора, метод `next()` или другие методы итератора вызовут исключение `ConcurrentModificationException`.

### Пример проблемы:
```java
ArrayList<String> list = new ArrayList<>();
list.add("A");
list.add("B");
list.add("C");

for (String item : list) {
    if (item.equals("B")) {
        list.remove(item);  // Это вызовет ConcurrentModificationException
    }
}
```

### Как правильно удалить элемент

**Использовать явный `Iterator`:** Вместо for-each цикла можно использовать явный `Iterator` и его метод `remove()`, который безопасно удаляет элементы во время итерации.
```java
Iterator<String> iterator = list.iterator();
while (iterator.hasNext()) {
    String item = iterator.next();
    if (item.equals("B")) {
        iterator.remove();  // Безопасно удаляет элемент
    }
}
```

**Использовать метод `removeIf` (начиная с Java 8):** Можно использовать метод `removeIf` для удаления элементов на основе условия.
```java
list.removeIf(item -> item.equals("B"));
```

## Особенности работы с `ArrayList`
- **Инициализация массива:** Изначально элементы массива указывают на `null`.
- **Увеличение размера (capacity):**
  - При добавлении элементов, если массив достигает предела, его размер увеличивается по формуле: `capacity = capacity + capacity / 2`.
  - Новый массив с увеличенным размером создаётся, элементы копируются, и добавляется новый элемент.

## Сложности операций
- **Медленный поиск по значению:** Требует прохода по всем элементам (O(n)).
- **Медленные операции вставки и удаления:** Необходимость сдвига элементов при изменении структуры (O(n)).

## Плюсы и минусы `ArrayList`
**Плюсы:**
- Быстрый поиск по индексу.
- Динамический размер.

**Минусы:**
- Медленный поиск по значению.
- Медленная вставка и удаление при переполнении массива.

# LinkedList

`LinkedList` — это структура данных, представляющая собой список, состоящий из узлов (нод), где каждый узел хранит данные и ссылку на следующий элемент.

## Пример объявления в Kotlin
```kotlin
val linkedList: LinkedList<String> = LinkedList()
```

## Пример объявления в Java
```java
LinkedList<String> linkedList = new LinkedList<>();
```

## Виды связных списков

**Односвязный список (Singly Linked List):**
- Узлы хранят ссылку только на следующий элемент.
- Добавление в начало: O(1).
- Добавление в конец: O(n), если нет указателя на последний элемент.
- Добавление по индексу: O(n).

**Двусвязный список (Doubly Linked List):**
- Узлы хранят ссылки как на следующий, так и на предыдущий элемент.
- Добавление в начало: O(1).
- Добавление в конец: O(1), если есть указатель на хвост.
- Добавление по индексу: O(n).

## Реализация интерфейсов
- **Queue:** Поддерживает принцип FIFO (First In, First Out).
- **Deque:** Поддерживает принципы FIFO и LIFO (Last In, First Out).

## Плюсы и минусы `LinkedList`
**Плюсы:**
- Быстрая вставка и удаление из середины списка.

**Минусы:**
- Операции модификации в середине требуют обхода списка.


# Set
Главная особенность это то что она хранит в себе уникальные элементы
Основные реализации Set:
HashSet:

Использует хэш-таблицу для хранения элементов.
Порядок элементов не гарантирован.
Эффективна для операций поиска.
LinkedHashSet:

Основана на HashSet с дополнительной связью для поддержания порядка вставки элементов.
Порядок элементов соответствует порядку их добавления.
TreeSet:

Реализует интерфейс NavigableSet, основан на TreeMap.
Поддерживает элементы в отсортированном порядке.
Эффективна для операций, где требуется сортировка.

# HashSet
HashSet — это коллекция, которая хранит уникальные элементы и основана на хэш-таблице. Эта структура данных обеспечивает быстрый доступ к элементам благодаря использованию хэширования.

Основные характеристики HashSet:
Уникальность элементов:

Все элементы в HashSet уникальны. Если попытаться добавить дубликат, он будет проигнорирован.
Хранение элементов:

HashSet использует хэш-таблицу, в которой элементы распределяются по корзинам (buckets) на основе их хэш-кодов (hashCode()).
Порядок элементов:

Порядок элементов не гарантируется. Элементы могут отображаться в произвольном порядке, зависящем от хэш-кодов и внутреннего состояния хэш-таблицы.
Нет синхронизации:

HashSet не синхронизирован. Для многопоточного доступа необходимо использовать Collections.synchronizedSet().
Основные методы HashSet:
add(E e):

Добавляет элемент в HashSet.
Возвращает true, если элемент был добавлен (не был дубликатом), иначе false.
remove(Object o):

Удаляет элемент из HashSet.
Возвращает true, если элемент был найден и удален, иначе false.
contains(Object o):

Проверяет, содержится ли элемент в HashSet.
Возвращает true, если элемент найден, иначе false.
size():

Возвращает количество элементов в HashSet.
clear():

Удаляет все элементы из HashSet.
isEmpty():

Проверяет, пустой ли HashSet.
Пример использования:
java
Копировать код
import java.util.HashSet;

public class HashSetExample {
    public static void main(String[] args) {
        HashSet<String> set = new HashSet<>();

        set.add("Apple");
        set.add("Banana");
        set.add("Orange");
        set.add("Apple"); // Дубликат, не будет добавлен

        System.out.println("HashSet: " + set);
        System.out.println("Contains 'Apple': " + set.contains("Apple"));
        set.remove("Banana");
        System.out.println("After removing 'Banana': " + set);
    }
}
Внутреннее устройство:
Хэширование:
Элементы хранятся на основе их хэш-кодов, что позволяет быстро находить элемент по его ключу.
Решение коллизий:
Когда два элемента имеют одинаковый хэш-код, они сохраняются в виде связного списка внутри соответствующей корзины. В Java 8 и выше для оптимизации используется дерево.
Сложность операций:
Добавление: O(1) в среднем случае. При большом количестве коллизий сложность может увеличиться до O(n).
Удаление: O(1) в среднем случае. При плохом распределении хэш-кодов может достигать O(n).
Поиск: O(1) в среднем случае. При коллизиях сложность может возрасти до O(n).
Преимущества HashSet:
Быстрые операции добавления, удаления и поиска.
Простота использования для задач, где важна уникальность элементов.
Ограничения HashSet:
Не гарантирует порядок элементов.
Не синхронизирован.
Может иметь высокие накладные расходы по памяти при большом количестве элементов и неравномерном распределении хэш-кодов.
HashSet — отличный выбор, когда необходимо быстрое выполнение операций и не важен порядок элементов.

HashMap
Характеристики:

Хранение: На основе хэш-таблицы.
Порядок: Порядок пар "ключ-значение" не гарантируется.
Коллизии: Решаются с помощью связных списков и, начиная с Java 8, деревьев.
Операции:
Вставка/удаление/поиск: Средняя сложность O(1).
Пример использования:

java
Копировать код
import java.util.HashMap;

public class HashMapExample {
    public static void main(String[] args) {
        HashMap<String, Integer> map = new HashMap<>();
        map.put("One", 1);
        map.put("Two", 2);
        map.put("Three", 3);
        
        System.out.println("Value for 'Two': " + map.get("Two"));
        map.remove("Two");
        System.out.println("Map after removing 'Two': " + map);
    }
}
LinkedHashMap
Характеристики:

Хранение: На основе хэш-таблицы с дополнительным связным списком для поддержания порядка.
Порядок: Сохраняет порядок вставки или порядок доступа.
Коллизии: Решаются аналогично HashMap, но с поддержанием порядка.
Операции:
Вставка/удаление/поиск: Средняя сложность O(1), но с дополнительными накладными расходами на поддержание порядка.
Пример использования:

java
Копировать код
import java.util.LinkedHashMap;

public class LinkedHashMapExample {
    public static void main(String[] args) {
        LinkedHashMap<String, Integer> map = new LinkedHashMap<>();
        map.put("One", 1);
        map.put("Two", 2);
        map.put("Three", 3);

        System.out.println("LinkedHashMap: " + map);
        map.put("Four", 4);
        System.out.println("After adding 'Four': " + map);
    }
}
TreeMap
Характеристики:

Хранение: На основе красно-черного дерева.
Порядок: Элементы хранятся в отсортированном порядке по ключу.
Коллизии: Коллизий как таковых нет, так как используется дерево.
Операции:
Вставка/удаление/поиск: Средняя сложность O(log n).
Пример использования:

java
Копировать код
import java.util.TreeMap;

public class TreeMapExample {
    public static void main(String[] args) {
        TreeMap<String, Integer> map = new TreeMap<>();
        map.put("One", 1);
        map.put("Two", 2);
        map.put("Three", 3);

        System.out.println("TreeMap (sorted): " + map);
        map.remove("Two");
        System.out.println("After removing 'Two': " + map);
    }
}
Сравнение:
Реализация	Порядок	Средняя сложность операций	Примечания
HashMap	Не гарантируется	O(1)	Быстрая, но неупорядоченная коллекция.
LinkedHashMap	Порядок вставки	O(1)	Сохраняет порядок вставки элементов.
TreeMap	Сортировка по ключу	O(log n)	Подходит для данных, требующих сортировки.
Выбор подходящей реализации:
HashMap: Когда нужен быстрый доступ к данным, и порядок не имеет значения.
LinkedHashMap: Когда требуется сохранить порядок добавления или порядок доступа.
TreeMap: Когда важна сортировка элементов по ключу.
Использование той или иной реализации зависит от конкретных требований к порядку и производительности вашего приложения.
